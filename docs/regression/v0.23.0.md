# Rapport de régression — v0.23.0 (STORY-19)

Deux nouveaux écrans (`book-equipes`, `book-joueurs`), un nouveau champ d'état (`state.bookBackTarget`) pour une cible de retour dynamique du Book, et 4 fichiers existants légèrement modifiés (`screen-accueil.js`, `screen-tireur.js`, `screen-book.js`, `state.js`). Aucune migration de données.

## Mise à jour de la checklist

**Mise à jour** : l'entrée STORY-17 reformulée pour refléter que la cible de retour du Book est désormais dynamique (plus un unique "écran Tireur" fixe), avec renvoi vers la nouvelle entrée STORY-19 pour le détail.

## Analyse de risque de régression croisée
Deux risques P1 identifiés par le Risk Analyst avant la story, tous deux vérifiés en conditions réelles :
1. **Retour cassé après consultation via une équipe** — testé explicitement sur les 3 chemins de retour (recherche, récents, roster d'équipe) : chacun ramène bien à son écran d'origine, y compris le bouton "Retour" de l'état vide du Book (testé séparément du bouton retour du header).
2. **Tireurs libres rendus difficiles à trouver** — testé par un cycle complet réel (recherche d'un nom inexistant → création → Book → retour vers la recherche), et par la vérification que le lien "🔍 Rechercher un tireur" est visible sans scroll sur un viewport mobile réel (375×667).

Un risque P2 (collision `state.equipeCourante` entre le flow Book et le flow Paramètres) a également été testé explicitement : navigation croisée Paramètres → Équipes → Joueurs puis Book par tireur → équipe différente → roster correct affiché, aucune contamination.
